# M4 rulings (privileged removal and system cleanup)

These are the decisions made while M4 was being built, where the plan was silent, wrong or overruled. Each one records the reason, and what it costs if it turns out wrong.

## Privilege and the batch script

**Escalation order and gating**
- Escalation tries run0 first (systemd 256 or newer), then pkexec, then sudo (only with a TTY). Detection uses the 60 s query runner.
- Real escalation is gated in layers:
  - `SystemPrivilegedRunner::run` refuses under `cfg(test)` or when root ≠ `/`.
  - `execute` / `execute_with` never escalate. `execute_many`, called through the CLI's `Privilege::for_run`, is the only path.
  - Debug builds refuse real escalation unless `CRUMBS_ALLOW_REAL_ESCALATION=1`.
  - `CRUMBS_TEST_PRIV_RUNNER` and `CRUMBS_TEST_BEFORE_EXECUTE` are debug-only and work only when root ≠ `/`.
  - Release builds refuse to start (exit 2) when `CRUMBS_ROOT` or any `CRUMBS_TEST_*` variable is set.
  - `tests/cli.rs` fails to compile outside a debug build.
- Why: a test once reached the real pkexec. Later, `cargo test --release` would have reached the real run0.

**One prompt per run**
- `execute_many` collects the privileged actions of every plan into a single `/bin/sh` batch.
- History keeps a batch id per plan.

**Marker transport**
- Step output is re-emitted with a `|` prefix on every line. Markers (`@@crumbs <i> <status>`) are parsed in order, by exact grammar.
- No step output can begin a line with `@@`, so markers cannot be forged, and no nonce is needed.
- Cost if wrong: step output is held in memory, and NUL bytes in it are dropped.

**Script header**
- `PATH`/`LC_ALL` are fixed and the `LD_*` variables are unset.
- `unset -f printf read command`, then `command unset IFS CDPATH BASHOPTS`. `BASHOPTS` is readonly in bash, which is why the `command` prefix is needed.

**Script size**
- The step body is defined once, as `__c`. Steps that share program, leading args and the last argument's directory share a `__t<n>` template, so each step line carries only the basename.
- The 120 KiB cap fits about 1000 core dumps. Past the cap, the error is generic: "select fewer items with -i".

**Partial batches**
- Zero markers means the escalation was denied (exit 5).
- If markers stop part-way, the step that was running is marked "may have partly run", later steps "not run" (exit 3). The message never claims that nothing changed.

## Package removal

**Pacman**
- Simulate with `pacman -Rs --print`, then run `pacman -Rn --noconfirm <exact simulated closure>`, without `-s`. This overrides plan Decision 4's `-Rns`.
- Why: root can never remove more than the preview listed. If the package database changes after the preview, pacman refuses rather than widening the removal.

**Verification and locking**
- `still_installed` returns `Result`. "Could not verify" counts as a failure (fail closed).
- Any entry at `db.lck`, including a dangling symlink, means the database is busy.

**Flatpak**
- Removal uses `--user`, `--system` or `--installation=<name>`, and never `--delete-data`.
- The still-installed check looks across all installations, which is conservative.

**Restore**
- Restore never reinstalls a package. It prints `pacman -S` for the package the user asked to remove and `pacman -S --asdeps` for the dependencies, including for a removal that only partly ran.

## Safety and paths

- **Fingerprint:** ctime is compared only for non-directories. A directory's ctime changes whenever its entries change, so active cache directories would be refused between preview and confirm.
- **Scope::System:** every directory from `/` down to the target must be root-owned and not writable by group or others. The target must be a regular file. It is checked again just before the batch runs.
- **History:**
  - The history directory and file are opened with `O_NOFOLLOW`, so a symlinked directory or file is refused.
  - Modes are made owner-only through an `O_PATH` fd and `/proc/self/fd`, so that a file at 0o044 can still be repaired.
  - A torn last line is terminated before the next append.

## System categories

- `journal_max` is validated with `^[0-9]+[KMGT]?$` and must be above 0. An invalid value fails the category closed, and no unvalidated text ever reaches a root argv.
- `system-temp` runs `systemd-tmpfiles --clean --prefix=/tmp --prefix=/var/tmp`, so the command matches its label and doesn't apply every age rule in tmpfiles.d.
- `orphan-pkgs` and `flatpak-unused-system` are opt-in. The preview shows the whole `-Rn` closure on its `as root:` line. On the dev machine, 39 orphans gave a 60-package closure.
- Plain `scan` and `clean` cover user categories only. Naming a system category implies `--system`. Combining a named category with the flag of the other kind (`--user` or `--system`) exits 2.

## Exit codes and manual commands

- Exit 5 has two paths:
  - No escalation program: crumbs stops before the prompt, `report` is null and nothing is written to history.
  - Prompt denied: `escalation_failed` is set and the attempt is recorded in history.
- `manual_commands` lists only actions that failed for lack of rights. It never lists actions refused by safety checks, or skipped cross-plan dependents.
- The consent note reads "these steps run with administrator rights; you will be asked once".
