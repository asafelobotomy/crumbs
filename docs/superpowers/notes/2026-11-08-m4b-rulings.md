# M4b rulings (system leftovers and unmanaged removal)

These are the decisions made while building M4b where the plan was silent, wrong or overruled. Each one gives the reason and what it costs if it turns out to be wrong.

## What counts as owned

- **The pacman index reads paths as raw bytes.** It never decodes names lossily, so a non-UTF-8 name is never indexed as a different path and wrongly reported "unowned".
- **The index fails closed.** `load_pacman` returns `Err` on any unreadable entry. The inventory's copy carries `complete`, and an incomplete index offers nothing.
  - Without a pacman database, nothing in `/etc` or `/opt` is offered. Unmanaged removal into `/opt` is refused with "package ownership is unknown".
- **Paths in tmpfiles.d count as owned.** The first real-system run offered `/etc/openvpn` for the installed openvpn package. No package lists that folder, but the package's tmpfiles.d recreates it. Rules are read from four directories: `/usr/lib`, `/usr/local/lib`, `/run` and `/etc`.
- **How a tmpfiles.d path covers a folder.**
  - A plain path covers a folder when it is that folder or lies below it.
  - A glob or `%` pattern covers a folder only if its leading components can glob-match the folder's.
  - A declared ancestor, such as `z /`, covers nothing.
  - Background: the earlier "the pattern's folder covers everything below it" rule let systemd's `R! /.#machine.*` hide every `/etc` and `/opt` entry.
  - Other details:
    - `%E` means `/etc`;
    - quoted fields are unquoted as systemd does;
    - a field that cannot be unquoted covers everything in its literal folder, which fails closed.

## Matching

- **Exec names are weak evidence.** A match based only on the program's file name is capped at Low. Any claim by another installed app marks a finding shared. Programs such as wine, python3 and electron are generic, and must not claim `/etc/<name>`.
- **Unmanaged targets need the app's real names.** These are its name, desktop-id stems, reverse-DNS id or display name, never the Exec file name.
  - Why: the Exec name comes from the same path being checked, so the check always passed. A planted `evil.desktop` with `Exec=/opt/inky/Inky` produced a 541 MB root delete of `/opt/inky`.
  - Cost: noti-fi (`org.notify.Panel` → `notify-panel`) can only be removed with `--leftovers-only`.
- **`ETC_NEVER` also covers `/opt` children,** and gained `subuid`, `subgid`, `kernel`, `cmdline.d`, `secureboot`, `crypttab.initramfs`, `machine-info` and `resolv.conf`.

## Root tree deletes

- **The step is a guarded `/bin/sh -c`.** The guard refuses with status 97, deleting nothing, in two cases:
  - pacman's lock exists, including as a dangling symlink;
  - root's mount namespace differs from the user's.

  Otherwise the step runs `exec rm -rf --one-file-system -- "$2"`.
  - `readlink` and `rm` come from `resolve_trusted`.
  - Why: crumbs checks mounts as the user. Root under run0 may live in another namespace, where a same-device bind mount would be invisible to that check and to `--one-file-system`.
- **Re-checks run as the user, once per run, immediately before the batch:**
  - the fingerprint;
  - mounts at or below the target (from mountinfo, without reading the tree);
  - the pacman lock;
  - the reloaded pacman index;
  - the tmpfiles.d paths;
  - a readable namespace.

  Any failure refuses only that target.
- **Directory fingerprints stay `(dev, ino, is_symlink)`.** The parent chain is root-only, and the mount and ownership re-checks cover the changes that matter.
- **Picked system leftovers have no dependency.** They run even when the app's own removal fails, with the same meaning as `--leftovers-only`.
  - Why: privileged steps cannot wait for other steps, so a dependency meant a picked leftover never ran.
  - Cost: a leftover you ticked may go although the package stayed.
- **Unmanaged plans:**
  - findings inside the target are dropped, because they go with it;
  - a home symlink to the program is trashed after the target is deleted;
  - a link in a protected path stays, with a note.

## Selection and display

- **System leftovers are never pre-selected.** `--yes` alone never deletes one; `-i` picks them. The preview notes how many were not selected, and `-i` marks them `(root)`.
- **`orphans --system` lists `/opt` only, never `/etc`.** It acts only through `--clean --select <listed path>` or `-i`.
- **Sizes of unreadable trees show `-`,** and totals read "X + unknown".

## Trash and restore

- **A home trash must lie under home,** for trashing, for safety and for restore alike.
- **A trash folder on another drive must be a private 0700 folder owned by the user,** and creating one and restoring from one apply the same rule. A refused root gets its own clear message.
- **Restoring a batch that only deleted things** says "nothing in this batch can be restored" and exits 0. Restoring a system-tree delete says it cannot be restored, even when that delete failed.
