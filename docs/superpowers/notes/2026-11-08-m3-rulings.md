# M3 rulings made during execution

Every decision the controller made on the user's behalf while running the M3 plan, in order: the decision, why, and what it costs if wrong.

- Ruling: Task 1 — accept '/home/**/x' now matches '/home/x' (** = zero segments, per brief); mixed 'foo**' treated as '**' (shields more) — cost if wrong: broader excludes.
- Ruling: Task 3 — accept: autostart stem equal to a strong identifier ignoring case = High (gutcheck.desktop vs GutCheck); shared detection still applies — cost if wrong: an autostart entry preselected when names differ only by case.
- Ruling: Task 3 — accept the cross-target residual: when an AppImage file action is dropped because an earlier target's planned folder contains it, its leftovers lose the dependency; if that earlier removal then fails, the later app's leftovers still run. Requires an AppImage stored inside another selected app's leftover folder AND that folder's removal failing — rare; recorded as an M4 follow-up (cross-plan gate) — cost if wrong: in that edge case an AppImage stays installed while its config is trashed (restorable).
- Ruling: Task 7 — accept implementer's extra caution (skip /tmp dirs containing sockets/fifos or that are separate mounts; skip symlinked browser cache dirs; missing files/ or info/ → trash scanner Err).
- Ruling: Task 7 — temp must also require atime older than the threshold (files a live session still reads, e.g. xauth cookies, keep fresh atimes), and the skip-prefix list gains: `xauth`, `.xauth`, `serverauth`, `sddm`, `gdm`, `lightdm`, `kde`, `plasma`, `dbus`, `.wine`, `nvidia`, `mozilla`, `vscode`, `pyright`, `jetbrains` — cost if wrong: fewer temp items listed.
- Ruling: Task 7 — browser labels become `<Browser> (<profile>) <cache dir name>` to avoid three identical labels per profile.
- Ruling: Task 7 — Decision 4 read as "per-mount .Trash-$uid not scanned in M3" (brief wording; safe) — cost if wrong: per-mount trash size not shown.
- Ruling: Task 7 — temp: refuse when env.uid == 0 (scanner returns Err "temp cleanup is not available as root"; verify(UserTemp) also refuses uid 0); open-file check via one pass over /proc/*/fd (+ /proc/*/maps) building a (dev,ino) set, skipping candidates or dirs containing any open inode; executor re-runs the staleness/open-fd check (still_stale) right before deleting a Scope::UserTemp item — cost if wrong: fewer temp items cleaned.
- Ruling: Task 7 — orphaned trash info items get label suffix " (trash info only)"; running-browser exe set gains `brave-origin` (dev machine runs Brave-Origin as `brave-origin`).
- Ruling: Task 7 — accept O_NOATIME directory listing (prevents the scan itself from refreshing atimes and defeating the recheck); accept cwd/exe added to the open-file set; atime rule is a no-op on noatime mounts (dev machine) — other checks still apply.
- Ruling: Task 7 — REVERSE R1: drop the atime requirement and the O_NOATIME listing entirely. atime is unreliable (noatime/relatime) and self-defeating with the size pass; protection = mtime age + prefix list (incl. xauth etc.) + open-file set + execute-time recheck + root refusal — cost if wrong: a temp file only read (never held open, not prefixed) by a live session for >7 days could be listed.
- Ruling: Task 8 — version compare: a missing component is less than a numeric one but greater than a non-numeric tag (2.0 > 2.0-beta, 1.0 < 1.0.1); equal max versions in different dirs are all kept — resolves the brief's internal contradiction — cost if wrong: a pre-release ordered differently (only affects which AppImage counts as old; unparseable never old).
- Ruling: Task 8 — running AppImage is KEPT (not listed) rather than "listed not preselected" (Decision 6 wording) — safer — cost if wrong: a running old version isn't shown.
- Ruling: Task 8 — flatpak-unused item: preselected=false from the scanner (flatpak decides; often nothing to remove); Task 11 carry: items of categories explicitly named on the `clean` command line are preselected (except running-blocked), so `crumbs clean flatpak-unused` runs it — cost if wrong: one extra word to run it.
- Ruling: Task 8 — compare_versions: a numeric vs non-numeric component is incomparable (None) → both kept (prevents `nightly`/`latest` making every numbered build old).
- Ruling: Task 9 — a batch restore selector skips Command entries (like failed/no-op entries) so restoring a clean batch doesn't exit 3 just because flatpak ran; selecting a command entry by id still reports "commands cannot be undone" — cost if wrong: none.
- Ruling: Task 10 — accept: `skipped` field on CategoryReport; naming --category scans exactly those even if config turns them off; inventory errors are warnings for scan (exit unchanged).
- Ruling: Task 11 — accept: act::apply takes cfg+errors (no leftover index for clean); uninstall report now says "moved X to the trash" for trashed sizes (more accurate); print_notes sanitises warnings everywhere; preview counts actions (a trash pair = 2 rows).
- Ruling: Task 11 — named-category preselection becomes fail-closed: `item.preselected || (named && item.category == FlatpakUnused)`; no note-text parsing — cost if wrong: naming a category doesn't tick items a scanner held back for other reasons (user can still pick them with -i).
- Ruling: final I4 — `--keep-data` on a full AppImage uninstall keeps config/data but REMOVES the app's own launchers and icons together with the AppImage file (so nothing dangles); leftovers-only unaffected — cost if wrong: user loses a launcher they'd recreate anyway.
- Ruling: final (reviewer-declined item) — `trash` category becomes opt-in like flatpak-unused: scanner preselected=false; runs only when named (`crumbs clean trash`). Reason: default `clean` would permanently empty the whole home trash incl. items crumbs itself trashed (breaks restore). Overrides plan Decision 7's "every item preselected" for this category — cost if wrong: one extra word to empty the trash.
- Ruling: final — also fix now: protect `/../x` clamps to `/x`; cache scanner skips non file/dir/symlink entries; /tmp must be root-owned with sticky bit for UserTemp; temp_age_days and log_age_days floor 1 (smaller → warning + 1); unknown-size category shows `?` not `0 B+`; docs updated.
